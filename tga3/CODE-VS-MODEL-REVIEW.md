# 确定性信息补齐与内容生成的分工审查

本次边界：代码只按已有运行时身份、动作索引或原始记录收集和复制信息。
事实提炼、哪些内容应合并、多条 Intel 的文字生成、报告内容与论证仍由 AI 完成。
不实施、也不再建议代码按语义预合并 Intel，或替 AI 生成报告固定正文。

## 图片中的四项已实现

1. Scout 第二轮按未覆盖 action 分批获得精确元数据和结果、附件的原文片段。
   明示截断、预览省略、二进制和缺失；保留完整文件路径，AI 需要时读取原文。
   输出与附件分别列出，不把重定向导致的空 stdout 误当成没有输出。
   附件明确标注为当前文件版本，不能冒充动作发生时的历史快照。
2. Scout MCP 连接绑定任务和智能体，只提交 action_id、claim、detail/topic。
   服务端关联动作来源、保存的正文和附件；可显式选择该动作的非空证据子集，禁止跨动作引用。
   两轮工具都不接受模型提供的任务或身份。
3. 最终候选仅提交 conclusion、rationale、finding_ids 和可选 answer_type/topic。
   身份从运行时连接取得，模型信息从任务运行记录取得，规范化请求生成稳定重试键。
   重试先返回已保存条目；新候选仍需消费原生 Hook 的黑板更新，不削弱新鲜度检查。
4. 第三轮的分组由 AI 决定。单条组只提交原始 ID，服务端原样复制正文及主题；
   多条组要求 AI 提供合并文字，代码只处理身份、来源、证据并集和格式校验。

## 还有哪些工作适合代码承担

| 机会 | 代码可完成的确定性工作 | 准确性条件与边界 |
|---|---|---|
| 报告证据路径映射 | 将 Finding 的作者、action ID、相对证据路径映射为 Reporter 的实际只读挂载路径，附文件存在性、大小和校验信息 | 只提供索引，不生成报告段落或替 AI 选择结论 |
| 传输错误重试 | 对已具备幂等键的同一请求自动进行有限次数的网络/临时服务错误重试 | 参数原样重发；校验失败、身份错误、来源缺失不能自动改内容“修复” |
| 引用 ID 查找 | AI 明确选择某条黑板序号后，由代码查出对应 Finding UUID、校验类型和任务归属 | AI 决定引用哪条；代码不能用相似度擅自替换引用对象 |
| 附件版本核验 | 动作结束时记录内容哈希，登记前核验是否改变，必要时保留原始版本 | 当前只记录附件路径，后续覆盖可能改变内容；发现变化要明示，不能猜测历史内容 |
| 已知文件的物理信息 | 自动提供编码标记、文件大小、完整性、可解析性等检查结果 | 只能使用可确定的格式或索引；不能把解析失败推断成文件没有价值或目标没有漏洞 |

## 当前已由代码承担

动作 ID、Intel ID、任务绑定、工具调用记录、正文留存、附件索引、覆盖率检查、
合并引用校验、证据路径校验和最终登记、Finding 复现方法关联、黑板增量投递与确认、
Token 汇总、容器清理均已有实现。无需再让模型抄写或重复验证这些机械信息。

仍应交给 AI：单次结果说明了什么、负面测试的适用边界、哪些情报需要合并、
多条内容如何准确表述、最终结论是否充分，以及报告应如何解释证据。
不增加 Worker 定期停下来审阅 logs 的阶段。
