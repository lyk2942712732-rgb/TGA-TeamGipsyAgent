# TGA3 故障排除指南

## 1 推荐诊断顺序

按依赖链从下到上排查，避免先重装全部组件：

1. 文件和 JSON 配置。
2. Docker daemon 和磁盘。
3. PostgreSQL 容器。
4. Worker 镜像。
5. TGA3 控制面。
6. Nginx 或 Vite 前端。
7. Provider 密钥和模型协议。
8. 单个动态 Worker 和任务数据。

先运行：

```bash
python3 部署验证脚本.py --preflight
python3 部署验证脚本.py --frontend-url http://127.0.0.1
```

## 2 PostgreSQL 无法启动

检查：

```bash
cd tga3
docker compose ps
docker compose logs --tail=200 postgres
docker compose exec postgres pg_isready -U tga3 -d tga3
ss -ltnp | grep ':5433'
```

常见原因：

- 5433 已被其他进程占用。
- Docker daemon 未运行。
- 数据卷权限或磁盘空间异常。
- 修改了 Compose 密码，但 `runtime.json` DSN 未同步。
- 旧数据卷的 schema 与当前代码不兼容。

开发环境且数据可丢弃时可重建卷；生产环境先备份并迁移，禁止直接删卷。

## 3 控制面启动失败

前台运行可看到完整异常：

```bash
cd tga3
.venv/bin/tga3 --config-dir config serve
```

systemd 日志：

```bash
systemctl status tga3 --no-pager
journalctl -u tga3 -n 200 --no-pager
```

重点检查：

- Python 是否为 3.11+。
- `.venv/bin/tga3` 是否存在。
- 四个 JSON 是否语法正确。
- Provider、模型、Agent 和协议引用是否一致。
- PostgreSQL DSN 是否可连接。
- 服务用户是否可读写 `config`、`data`，并可访问 Docker daemon。

## 4 健康检查失败

```bash
curl -v http://127.0.0.1:8083/api/v3/health
ss -ltnp | grep ':8083'
```

预期响应：

```json
{"status":"ok","service":"tga3"}
```

连接拒绝通常表示进程未启动或监听端口被改动。HTTP 422 多与配置校验相关。Nginx 返回 502 时，先验证直连 8083，再检查 Nginx upstream。

## 5 前端页面打不开或刷新 404

开发模式：

```bash
cd apps/web
npm ci
npm run build
npm run dev
```

生产模式：

```bash
test -f /opt/TGA-TeamGipsyAgent/apps/web/dist/index.html
sudo nginx -t
sudo tail -n 100 /var/log/nginx/error.log
curl -I http://127.0.0.1/
```

刷新子路由 404 通常说明 Nginx 缺少 `try_files $uri $uri/ /index.html;`。页面能打开但 API 失败时，检查 `/api/v3/` 代理和控制面健康。

## 6 前端开发代理失败

Vite 默认把 `/api` 代理到 `http://127.0.0.1:8083`。若控制面运行在其他地址：

```bash
cd apps/web
TGA_API_PROXY_TARGET=http://<控制面地址>:8083 npm run dev
```

浏览器直接请求 8083 不是推荐生产方式。生产前端应同源请求 Nginx 的 `/api`。

## 7 Worker 镜像构建失败

```bash
cd tga3
docker system df
df -h /var/lib/docker
DOCKER_BUILDKIT=1 ./scripts/build-images.sh
```

常见原因：

- Kali CDN 或 PyPI 网络不稳定。
- Docker bridge 无法使用宿主代理或 Fake-IP DNS。
- 磁盘不足。
- 同时运行了多个构建脚本。

替代参数：

```bash
KALI_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/kali \
DOCKER_BUILD_NETWORK=host \
./scripts/build-images.sh
```

若 `host` 网络不可用，改用 `bridge`。不要关闭 HTTPS 证书校验来解决镜像问题。

## 8 基础镜像工具自检失败

```bash
./scripts/verify-worker-image.sh tga3-ctf-base:local
docker run --rm --entrypoint /bin/bash tga3-ctf-base:local -lc 'python --version; command -v nmap; command -v gdb'
```

如果镜像存在但工具缺失，重新构建基础镜像并观察最早失败的 Dockerfile 层。不要只在运行中的 Worker 容器手工安装工具，因为任务容器会被回收。

## 9 创建任务时 Worker 启动失败

检查控制面日志和 Docker：

```bash
journalctl -u tga3 -n 200 --no-pager
docker ps -a --filter label=tga3.task_id
docker image inspect tga3-worker-openai:local >/dev/null
docker image inspect tga3-worker-claude:local >/dev/null
```

常见原因：

- 镜像名与 `runtime.json` 不一致。
- 服务账户不在 `docker` 组。
- workspace 或 artifact 目录无法设为 Worker UID/GID。
- Docker 网络不存在。
- CPU、内存或 PID 限制超出宿主资源。
- `host.docker.internal` 网关或 8083 防火墙规则阻止回连。

## 10 Worker 已启动但无法连接控制面

查看容器日志：

```bash
docker logs --tail=200 <worker容器>
docker inspect <worker容器> --format '{{json .NetworkSettings.Networks}}'
```

在临时容器中检查宿主网关：

```bash
docker run --rm --add-host host.docker.internal:host-gateway \
  curlimages/curl:latest \
  http://host.docker.internal:8083/api/v3/health
```

确认 `runtime.json` 的 `control_ws_url` 和 `blackboard_mcp_url` 端口与 `listen_port` 一致。若控制面只绑定 127.0.0.1，bridge Worker 通常无法访问。

## 11 模型调用失败

检查配置时不要打印密钥：

```bash
python3 - <<'PY'
import json
from pathlib import Path
p = Path('tga3/config/models.json')
d = json.loads(p.read_text(encoding='utf-8'))
for provider in d['providers']:
    keys = provider.get('api_keys', [])
    selected = provider.get('selected_api_key_id')
    configured = any(k.get('id') == selected and bool(k.get('api_key')) for k in keys)
    print(provider['id'], 'configured=' + str(configured), 'models=' + str(len(provider.get('models', []))))
PY
```

确认：

- Agent 的 `provider_id` 和 `model_id` 存在。
- `selected_api_key_id` 指向非空密钥。
- OpenAI Agents SDK 使用 OpenAI 兼容协议。
- Claude Agent SDK 使用 `anthropic` 协议。
- Base URL 是 Provider 根地址，且服务器能访问。
- 模型名称、配额、超时和账户权限正确。

## 12 配置保存返回 422

配置接口会做跨文件验证。读取响应中的 `message`，通常涉及：

- 缺少四个必需 Agent。
- 缺少八个必需场景。
- Agent 引用了不存在的 Provider 或模型。
- SDK 与协议不匹配。
- 资源或 cadence 数值超出范围。

恢复最近一次配置备份后，逐项修改并保存，不要同时大批替换多个文件。

## 13 SSE 对话不更新

确认浏览器请求 `/api/v3/tasks/<id>/dialogue/stream` 持续连接。Nginx 应包含：

```nginx
proxy_buffering off;
proxy_cache off;
proxy_read_timeout 1h;
```

若代理或上游负载均衡器仍设置较短空闲超时，也会断开 SSE。先直连 8083 比较，再逐层检查。

## 14 磁盘快速增长

```bash
du -sh tga3/data/*
docker system df
docker ps -a --filter label=tga3.task_id
```

清理前确认任务和保留策略。优先在应用层删除不再需要的任务，让控制面回收其容器和数据。不要无差别删除 `data`、数据库卷或全部 Docker volumes。

## 15 收集诊断信息

提供问题报告时可收集：

```bash
python3 部署验证脚本.py --preflight
docker compose -f tga3/compose.yaml ps
docker image ls 'tga3-*'
systemctl status tga3 --no-pager
journalctl -u tga3 -n 200 --no-pager
sudo nginx -t
```

提交前删除 API 密钥、用户上传内容、任务提示、Artifact 路径中的敏感标识和完整内部地址。
