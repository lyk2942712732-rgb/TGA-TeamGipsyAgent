# TGA3 配置文件说明

## 1 配置来源

TGA3 只从仓库内的 `tga3/config` 读取持久配置。Provider、模型、API 密钥和 Agent 提示词不会被宿主环境变量覆盖。前端配置中心和 JSON 文件操作的是同一份数据。

配置文件包括：

| 文件 | 内容 | 是否含敏感信息 |
|---|---|---|
| `models.json` | Provider、协议、Base URL、API 密钥、模型 | 是 |
| `agents.json` | 四个 Agent 的角色、SDK、模型绑定、轮次和系统提示词 | 可能 |
| `scenes.json` | 八类任务场景及提示词 | 否 |
| `runtime.json` | 数据库、监听、目录、Worker 镜像、资源和节奏 | 可能 |
| `skills/` | Agent 可按名读取的 Markdown Skill 包 | 视内容而定 |

## 2 修改方式

推荐流程：启动控制面后，通过前端配置中心修改。后端会先验证完整配置，验证失败不会替换现有文件。

需要离线编辑时：

```bash
cd tga3
cp -a config "config.backup.$(date +%Y%m%d-%H%M%S)"
jq empty config/models.json
jq empty config/agents.json
jq empty config/scenes.json
jq empty config/runtime.json
```

编辑后启动控制面进行完整校验。不要在服务写配置时同步手工编辑同一文件。

## 3 models.json

### 3.1 Provider 字段

| 字段 | 说明 |
|---|---|
| `id` | Provider 唯一标识，供 Agent 绑定 |
| `name` | 界面显示名称 |
| `preset_id` | 内置供应商预设 |
| `built_in` | 内置供应商不可删除，但可不配置密钥 |
| `protocols` | 可用协议：`openai_responses`、`openai_chat_completions` 或 `anthropic` |
| `base_url` | 供应商根地址；预设会补全发现和推理路径 |
| `api_keys` | 一个或多个命名密钥 |
| `selected_api_key_id` | 当前使用的密钥 ID |
| `models` | 已配置或发现的模型列表 |

### 3.2 模型字段

| 字段 | 默认或约束 | 说明 |
|---|---|---|
| `id` | Provider 内唯一 | Agent 绑定使用的稳定 ID |
| `name` | 供应商模型名 | 实际请求名称 |
| `max_output_tokens` | 默认 8192，至少 1 | 最大输出 token |
| `timeout_seconds` | 默认 180，至少 1 | 单次请求超时 |
| `temperature` | 可选，0 到 2 | 模型支持时使用 |

首次部署时，默认 OpenAI 和 Anthropic 密钥为空。至少为实际绑定的 Provider 配置非空密钥，否则任务启动或宿主 Agent 调用会失败。

### 3.3 密钥保护

```bash
deploy_user="$(id -un 1000)"
deploy_group="$(id -gn "$deploy_user")"
sudo chown "$deploy_user:$deploy_group" /opt/TGA-TeamGipsyAgent/tga3/config/models.json
sudo chmod 600 /opt/TGA-TeamGipsyAgent/tga3/config/models.json
```

备份配置时使用加密介质或受控密钥库。排错输出不得打印 `api_key` 值。

## 4 agents.json

配置必须包含以下 Agent：

| ID | 角色 | 默认运行时 | 运行位置 |
|---|---|---|---|
| `supervisor` | supervisor | `openai_agents` | 宿主控制面 |
| `worker-openai` | worker | `openai_agents` | 动态容器 |
| `worker-claude` | worker | `claude_agent` | 动态容器 |
| `reporter` | reporter | `openai_agents` | 宿主控制面 |

每个 Agent 主要字段：

| 字段 | 说明 |
|---|---|
| `display_name` | 界面显示名 |
| `role` | `supervisor`、`worker` 或 `reporter` |
| `runtime` | `openai_agents` 或 `claude_agent` |
| `provider_id` | 指向 `models.json` Provider |
| `model_id` | 指向 Provider 下模型 |
| `protocol` | 实际推理协议 |
| `max_turns_per_cycle` | 每个工作周期最大轮次，1 到 50 |
| `system_prompt` | 完整角色约束和输出协议 |

协议必须匹配 SDK：Claude Agent SDK 只接受 `anthropic`，OpenAI Agents SDK 不接受 `anthropic`。Provider 也必须声明所选协议。

不要只修改模型名称而遗漏 `model_id` 或 Agent 绑定。最稳妥的方式是先在 Models 页面完成发现，再在 Solver 页面选择。

## 5 scenes.json

系统要求存在以下场景 ID：

- `penetration_test`
- `incident_response`
- `vulnerability_research`
- `reverse_engineering`
- `pwn`
- `security_misc`
- `cryptography`
- `forensics`

每个场景包含稳定 `id`、显示 `name`、`description` 和 `system_prompt`。修改提示词不会改变旧任务已经写入黑板的场景条目，新任务立即使用保存后的版本。

## 6 runtime.json

### 6.1 连接和监听

| 字段 | 默认值 | 说明 |
|---|---|---|
| `postgres_dsn` | `postgresql://tga3:tga3@127.0.0.1:5433/tga3` | 控制面数据库连接 |
| `control_ws_url` | `ws://host.docker.internal:8083/internal/agents` | Worker 回连控制面 |
| `blackboard_mcp_url` | `http://host.docker.internal:8083/mcp` | Worker 访问 MCP |
| `listen_host` | `0.0.0.0` | 控制面监听地址 |
| `listen_port` | `8083` | 控制面端口 |

`listen_host` 不能简单改为 `127.0.0.1`，否则 bridge 网络中的 Worker 通常无法通过宿主网关回连。生产环境应使用防火墙或安全组限制 8083 的外部访问。

### 6.2 数据目录

| 字段 | 默认值 | 权限 |
|---|---|---|
| `workspace_root` | `./data/workspaces` | Worker 读写 |
| `input_root` | `./data/inputs` | Worker 只读挂载 |
| `artifact_root` | `./data/artifacts` | Worker 读写 |
| `writeup_root` | `./data/writeups` | 控制面读写 |
| `skills_root` | `./config/skills` | 控制面管理，Agent 按需读取 |

相对路径以 `tga3` 项目根目录为基准。动态 Worker 使用固定 UID/GID，目录权限错误会在任务创建时暴露。

### 6.3 镜像

```json
{
  "worker-openai": "tga3-worker-openai:local",
  "worker-claude": "tga3-worker-claude:local"
}
```

镜像标签修改后，必须先构建或拉取对应镜像。控制面不会自动构建镜像。

### 6.4 Docker 资源

| 字段 | 默认值 | 约束或含义 |
|---|---:|---|
| `network` | `bridge` | Worker 使用的 Docker 网络 |
| `cpu_cores` | 2.0 | 大于 0，最多 64 |
| `memory_mb` | 4096 | 256 到 131072 |
| `pids_limit` | 512 | 32 到 65536 |
| `worker_uid` | 1000 | 1 到 65535 |
| `worker_gid` | 1000 | 1 到 65535 |
| `cap_add` | `NET_RAW`, `SYS_PTRACE` | 网络探测和二进制调试 |

提高资源上限前要按并行 Worker 数量计算宿主容量。不要加入 `SYS_ADMIN`、宿主设备或 Docker socket 挂载。

### 6.5 节奏参数

| 字段 | 默认秒数 | 说明 |
|---|---:|---|
| `worker_sync_seconds` | 90 | Worker 漏事件兜底同步 |
| `supervisor_debounce_seconds` | 2 | Intel 静默合并窗口 |
| `supervisor_intel_max_wait_seconds` | 10 | Intel 批次最大等待 |
| `supervisor_advice_interval_seconds` | 60 | Intel 触发建议的最小间隔 |
| `supervisor_silence_seconds` | 90 | 无共享进展后的沉默检查 |
| `finalization_grace_seconds` | 30 | 最终候选后的收敛宽限期 |

这些值有代码级范围校验。缩短间隔会增加模型调用和数据库压力，调整后应进行真实任务压测。

## 7 前端代理配置

`apps/web/vite.config.ts` 默认将 `/api` 代理到 `http://127.0.0.1:8083`。开发或预览时可临时指定：

```bash
TGA_API_PROXY_TARGET=http://127.0.0.1:8083 npm run dev
```

生产构建不把 API 主机写死在静态文件中；浏览器请求同源 `/api`，由 Nginx 转发。

## 8 生效规则

| 修改 | 生效时机 |
|---|---|
| Provider、模型、Agent、场景 | 新任务创建时 |
| Worker 镜像和资源 | 新 Worker 创建时 |
| cadence | 新任务或新周期读取配置时，以实现为准，建议重启 |
| `listen_host`、`listen_port`、`postgres_dsn` | 重启控制面后 |
| Nginx 配置 | `nginx -t` 通过并 reload 后 |

修改前备份，修改后运行 `部署验证脚本.py --preflight`，再重启并执行完整验证。
