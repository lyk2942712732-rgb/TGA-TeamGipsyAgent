# TGA3 详细手动部署指南

## 1 适用范围

本指南适用于单台 Linux 主机上的开发、演示和单机生产部署。命令默认从 `TGA-TeamGipsyAgent` 仓库根目录执行；生产示例将仓库放在 `/opt/TGA-TeamGipsyAgent`。若源码位于其他位置，请替换路径。

项目唯一的完整部署编排是 `部署手册/deploy.py`，推荐通过 `./deploy.sh` 执行。本指南后续分解命令用于理解、人工核验和故障恢复，不构成第二套自动部署实现。

## 2 部署前检查

### 2.1 系统和资源

```bash
uname -a
df -h
free -h
nproc
```

建议准备 8 核 CPU、16 GB 内存和 50 GB 以上可用磁盘。默认两个 Worker 各可使用 2 CPU 和 4 GB 内存；镜像构建阶段还需要额外资源。

### 2.2 软件

```bash
python3 --version
python3 -m venv --help >/dev/null
node --version
npm --version
docker --version
docker compose version
docker compose up --help | grep -- --wait
docker info >/dev/null
```

Python 必须为 3.11 或更高版本。Docker daemon 必须可访问；部署用户应在 `docker` 组中，或者在允许的运维流程中使用 sudo。

Debian 或 Ubuntu 可安装基础依赖：

```bash
sudo apt update
sudo apt install -y git curl python3 python3-venv python3-pip nginx
```

RHEL、Rocky Linux 或 AlmaLinux 可使用：

```bash
sudo dnf install -y git curl python3 python3-pip nginx
```

不同发行版仓库提供的 Python 版本可能不同。安装后必须重新执行 `python3 --version`，确认达到 3.11；否则按发行版的软件模块或组织软件源安装 Python 3.11+。

Docker Engine、Docker Compose v2 和 Node.js 应按所在发行版或组织的软件源与版本策略安装。安装后重新登录，使 `docker` 组权限生效。

## 3 获取和确认源码

```bash
cd /opt
sudo git clone <仓库地址> TGA-TeamGipsyAgent
sudo chown -R "$USER":"$USER" /opt/TGA-TeamGipsyAgent
cd /opt/TGA-TeamGipsyAgent
git status --short

若源码由压缩包交付，解压后至少应存在：

```

## 4 启动 PostgreSQL

```bash
cd /opt/TGA-TeamGipsyAgent/tga3
docker compose config
docker compose up -d --wait postgres
docker compose ps
docker compose exec postgres pg_isready -U tga3 -d tga3
```

数据库默认连接串为：

```text
postgresql://tga3:tga3@127.0.0.1:5433/tga3
```

生产环境修改密码时，必须同步修改 `compose.yaml` 和 `config/runtime.json`。

## 5 构建 Worker 镜像

```bash
cd /opt/TGA-TeamGipsyAgent/tga3
chmod +x scripts/*.sh
./scripts/build-images.sh
```

此步骤依次构建：

1. `tga3-ctf-base:local`
2. `tga3-worker-openai:local`
3. `tga3-worker-claude:local`

基础镜像会安装 Kali headless、Pwn、逆向、取证、密码和多媒体分析工具，首次构建可能较慢。网络不稳定时可使用：

```bash
KALI_MIRROR=https://mirrors.tuna.tsinghua.edu.cn/kali \
DOCKER_BUILD_NETWORK=host \
./scripts/build-images.sh
```

Docker Desktop 或宿主网络模式不可用时，将 `DOCKER_BUILD_NETWORK` 改为 `bridge`。

验证镜像：

```bash
docker image ls 'tga3-*'
./scripts/verify-worker-image.sh tga3-ctf-base:local
```

## 6 安装控制面

```bash
cd /opt/TGA-TeamGipsyAgent/tga3
python3 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/pip install '.[control]'
```

开发或测试环境需要测试工具时：

```bash
.venv/bin/pip install '.[control,dev]'
.venv/bin/pytest
.venv/bin/ruff check src tests
```

## 7 构建前端

```bash
cd /opt/TGA-TeamGipsyAgent/apps/web
npm ci
npm test
npm run build
test -f dist/index.html
```

`npm ci` 严格使用 `package-lock.json`，适合可复现部署。不要在生产部署时删除锁文件后改用无锁安装。

## 8 配置系统

### 8.1 文件权限

控制面需要写入 `tga3/config` 和 `tga3/data`。默认 Worker 使用 UID/GID `1000:1000`，运行控制面的账户也应使用相同 UID/GID，否则创建任务目录时可能无权调整属主。先确认账户并设置权限：

```bash
deploy_user="$(id -un 1000)"
deploy_group="$(id -gn "$deploy_user")"
test "$(id -u "$deploy_user")" = "1000"
test "$(id -g "$deploy_user")" = "1000"
sudo usermod -aG docker "$deploy_user"
sudo mkdir -p /opt/TGA-TeamGipsyAgent/tga3/data
sudo chown -R "$deploy_user:$deploy_group" /opt/TGA-TeamGipsyAgent/tga3/config /opt/TGA-TeamGipsyAgent/tga3/data
sudo chmod -R u+rwX,go-rwx /opt/TGA-TeamGipsyAgent/tga3/config
sudo chmod -R u+rwX,g+rwX,o-rwx /opt/TGA-TeamGipsyAgent/tga3/data
```

若必须使用其他 UID/GID，应以同一数值重建基础 Worker 镜像，并同步修改 `runtime.json` 的 `worker_uid`、`worker_gid`。只修改目录权限或只修改运行时配置都不完整。

### 8.2 Provider 和 Agent

启动控制面后在前端“配置中心”设置 Provider 根地址、API 密钥和模型，再在 Solver 页面绑定 Agent。也可在受控环境中直接编辑：

- `tga3/config/models.json`
- `tga3/config/agents.json`
- `tga3/config/scenes.json`
- `tga3/config/runtime.json`

`models.json` 中的 API 密钥是明文敏感信息。不要提交到公共仓库或写入命令行历史。

## 10 生产服务安装

源码提供 systemd 和 Nginx 示例：

```bash
sudo cp /opt/TGA-TeamGipsyAgent/tga3/deploy/tga3.service /etc/systemd/system/tga3.service
deploy_user="$(id -un 1000)"
deploy_group="$(id -gn "$deploy_user")"
sudo mkdir -p /etc/systemd/system/tga3.service.d
printf '[Service]\nUser=%s\nGroup=%s\nSupplementaryGroups=docker\n' \
  "$deploy_user" "$deploy_group" \
  | sudo tee /etc/systemd/system/tga3.service.d/10-account.conf >/dev/null
sudo systemctl daemon-reload
sudo systemctl enable --now tga3
sudo systemctl status tga3 --no-pager

sudo cp /opt/TGA-TeamGipsyAgent/tga3/deploy/nginx-tga3.conf /etc/nginx/sites-available/tga3
sudo ln -sfn /etc/nginx/sites-available/tga3 /etc/nginx/sites-enabled/tga3
sudo nginx -t
sudo systemctl reload nginx
```

示例 unit 固定使用 `/opt/TGA-TeamGipsyAgent`，并原本使用 `tga3` 账户。上述 drop-in 会覆盖为 UID/GID 1000 的实际运行账户，并通过 supplementary group 访问 Docker。若源码路径不同，复制前还要编辑 `WorkingDirectory`、`ExecStartPre` 和 `ExecStart`。

## 11 验证部署

```bash
cd /opt/TGA-TeamGipsyAgent/部署手册
python3 部署验证脚本.py \
  --source-dir /opt/TGA-TeamGipsyAgent \
  --api-url http://127.0.0.1:8083 \
  --frontend-url http://127.0.0.1 \
  --require-api-key
```

手工检查：

```bash
curl -fsS http://127.0.0.1:8083/api/v3/health
curl -I http://127.0.0.1/
docker compose -f /opt/TGA-TeamGipsyAgent/tga3/compose.yaml ps
docker ps -a --filter label=tga3.task_id
journalctl -u tga3 -n 100 --no-pager
```

最后在界面创建一个范围明确的授权测试任务，确认两个 Worker 启动、对话流更新、停止任务后容器回收、报告可下载。

## 12 停止和重启

开发前台进程使用 `Ctrl+C` 停止。生产环境：

```bash
sudo systemctl restart tga3
sudo systemctl stop tga3
sudo systemctl start tga3
```

停止数据库前先停止控制面：

```bash
sudo systemctl stop tga3
cd /opt/TGA-TeamGipsyAgent/tga3
docker compose stop postgres
```
